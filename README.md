# Предложка канала «42 CONFESSION»

Telegram-бот на языке [Kiva](https://github.com/crimbrodev/kivac-plus), через который подписчики присылают работы (арты, видео, GIF, файлы, текст) про 42 братух. Админы проверяют заявки, одобренные бот сам публикует в канал.

- Отправитель выбирает художника и братух из выпадающего списка (inline-режим Telegram) или предлагает новых.
- Заявку на работу, на нового художника или братуху видят все админы; можно опубликовать/добавить, исправить или отклонить с причиной.
- Отправитель сам решает, подписать ли его в посте; по умолчанию — анонимно.
- Данные (справочники, заявки, шаги диалогов) лежат в Postgres, бот переживает перезапуск посреди заявки.
- Экраны и итоги заявок приходят с баннером: пиксельная мозаика своей формы и одно слово (`assets/banners/`, стиль описан в `assets/STYLE.md`).

Kiva собирается под x86-64 Linux, поэтому бот работает только на нём.

## Что понадобится

| Что | Arch / EndeavourOS | Debian / Ubuntu |
| --- | --- | --- |
| компилятор C, make, git | `base-devel git` | `build-essential git` |
| ассемблер | `nasm` | `nasm` |
| библиотеки | `curl jansson postgresql-libs` | `libcurl4-openssl-dev libjansson-dev libpq-dev` |
| база данных | любой Postgres 13+ | то же |

Для `make test` ещё нужны [uv](https://docs.astral.sh/uv/) и Docker (или готовый Postgres в `TEST_DATABASE_URL`).

## Настройка

1. В [@BotFather](https://t.me/BotFather): создайте бота и скопируйте токен, затем выполните `/setinline` и задайте подсказку для поля ввода — без этого выпадающий список не работает.
2. Создайте базу в Postgres.
3. Сделайте бота админом канала с правом публиковать сообщения.
4. `cp .env.example .env` и заполните значения (описание — в самом файле). Свой Telegram-id покажет команда `/id` у бота. Для публичного канала в `CHANNEL_ID` достаточно `@имя`, для закрытого нужен числовой id вида `-100…`.
5. Каждый админ один раз должен написать боту `/start`: иначе Telegram не даст боту написать ему первым.

## Сборка и запуск

```sh
make        # первый запуск сам скачивает и собирает компилятор Kiva в .kiva/
make run    # читает .env (как dotenv, не как shell: «&» в DATABASE_URL допустим) и запускает build/tgbot
```

Схема БД (`sql/schema.sql`) применяется при каждом старте, поэтому отдельных миграций пока нет.

Баннеры бот читает из каталога `assets/banners` относительно места запуска (другой путь — `BANNERS_DIR`). Нет файлов — экраны приходят обычным текстом, а в журнал при старте пишется предупреждение. Перерисовать баннеры после правки стиля: `make banners`.

## Проверка

```sh
make test
```

Тест запускает настоящий бинарник против поддельного Bot API и временного Postgres (поднимается в Docker, либо берётся из `TEST_DATABASE_URL`) и проводит через бота сценарии: заявка на работу от начала до публикации, альбом, текст, отказ, правка админом, повторные и чужие нажатия, сбой публикации, заявки на художников и братух, перезапуск посреди заявки, баннеры (загрузка файлом и по `file_id`, смена картинки на месте, замена устаревшего `file_id`, работа без файлов).

## Устройство

- `src/` — бот, файлы склеиваются Makefile в один исходник (в Kiva нет модулей, порядок файлов не важен): `core.k` — окружение, арена памяти, строки и UTF-8; `json.k` — jansson; `db.k` — libpq; `tg.k` — Bot API; `model.k` — пользователи, заявки, справочники; `post.k` — текст поста и отправка; `ui.k`, `wizard.k` — панель и экраны; `user.k` — сообщения и кнопки пользователей; `admin.k` — проверка заявок; `inline.k` — выпадающий список; `main.k` — цикл `getUpdates`.
- `sql/schema.sql` — схема БД.
- `assets/` — шрифт Waoki, генератор баннеров `make_banners.py`, готовые `banners/*.jpg` и описание стиля `STYLE.md`.
- `scripts/setup-kiva.sh` — сборка компилятора Kiva; `scripts/run.sh` — запуск с переменными из `.env`.
- `tests/e2e.py` — сквозной тест.

Особенности Kiva, которые важно помнить при доработке:

- Типов нет: любое значение — 64-битное слово, указатели и константы C-библиотек записаны числами.
- Нет `&&` и `||`: условия собираются через `&` и `|` над сравнениями в скобках. Эти операторы побитовые и приоритетнее сравнений, поэтому операнды обязаны быть 0 или 1.
- Сравнения беззнаковые, `int`-результаты C-функций маскируются `& 0xFFFFFFFF`.
- C-функции с более чем шестью аргументами вызываются неверно, поэтому запросы к Postgres собираются строкой (`PQescapeLiteral` для каждого значения), а у функций ≤ 6 параметров.
- В цикле `for` оператор `continue` пропускает приращение — используйте `while`.
- Временные строки живут на арене (`alloc`) до конца обработки update; строки из разобранного JSON нужно копировать (`s_dup`), если они переживают `json_release`.
