# AGENTS.md — карта проекта

Telegram-бот «предложка» канала **42 CONFESSION**: подписчики присылают работы, админы проверяют, бот публикует в канал. Написан на языке Kiva под x86-64 Linux, данные лежат в Postgres.

Пользовательская документация — `README.md`. Здесь — навигация по коду и правила, без которых правки легко ломают бота. Оба файла — часть проекта: **README.md и AGENTS.md нужно всегда поддерживать актуальными**, если меняются команды, окружение, структура файлов или поведение бота.

## Инструменты

Файлы читаются, ищутся и правятся встроенными инструментами, а не shell-командами:

- чтение — `Read` (большие файлы — с `offset`/`limit`), а не `cat`, `sed -n`, `awk`, `less`, `more`;
- поиск — `Grep` и `Glob`, а не `grep`, `rg`, `find`, `ls -R`;
- правка — `Edit` и `Write`, а не `sed -i`, `awk`, `perl -pi`, `tee`, `truncate`.

Shell нужен для сборки, запуска тестов, git и служебных скриптов, а не для чтения или правки исходников.

Вывод команд **не обрезать** через `head`, `tail`, `sed -n '1,50p'` и подобное — смотрите его целиком. Ограничители самой команды (`git log -n 5`, `--limit`) допустимы.

## Команды

| Команда | Что делает |
| --- | --- |
| `make` | Собирает `build/tgbot`; при первом запуске скачивает и собирает компилятор Kiva в `.kiva/` |
| `make run` | Запускает бота с переменными из `.env` (файл читает `scripts/run.sh`, путь можно задать через `ENV_FILE`) |
| `make test` | Собирает основной бинарник и гоняет `tests/e2e.py` |
| `uv run --script tests/e2e.py [сценарий ...]` | Только тесты; без аргументов — все сценарии, с аргументами — выбранные по имени функции |
| `make banners` | Перерисовывает `assets/banners/*.jpg` |
| `make avatar` | Перерисовывает `assets/avatar.jpg` (ставится через @BotFather) |
| `make clean` | Удаляет `build/` |

`make test` поднимает временный Postgres в Docker либо берёт `TEST_DATABASE_URL`. Тест между сценариями делает `DROP SCHEMA public CASCADE`: `TEST_DATABASE_URL` должен указывать только на одноразовую базу.

## Окружение и постоянные значения

Обязательные переменные (см. `.env.example`): `BOT_TOKEN`, `DATABASE_URL`, `ADMIN_IDS` (до 16 id через запятую), `CHANNEL_ID` (`@имя` или `-100…`). Бот читает их из окружения, `.env` разбирает `scripts/run.sh` как dotenv, а не как shell.

В коде жёстко заданы и **не должны снова становиться переменными окружения**:

- адрес Bot API — `tg_base` в `src/tg.k` (`https://api.telegram.org`);
- файл схемы — `sql/schema.sql`;
- каталог баннеров — `assets/banners`;
- прокси — не используется: в `tg_run` стоит `CURLOPT_PROXY` с пустой строкой, переменные вида `all_proxy` игнорируются.

Пути к схеме и баннерам относительны рабочему каталогу, поэтому бота запускают из корня проекта (или каталога, где есть `sql/` и `assets/`). Тест это учитывает.

Адрес Bot API в тестовой сборке подменяется: `tests/e2e.py` вызывает `make build/tgbot-test API_URL=http://127.0.0.1:ПОРТ`, а `Makefile` заменяет строку в склеенном исходнике через `sed`. Если меняется литерал адреса в `src/tg.k`, нужно поправить и `Makefile`.

## Как проходит заявка

1. Пользователь нажимает «Предложить работу» — создаётся `requests` со `status='draft'`, шаг пишется в `users.state` (`w_media`, `w_artist`, …).
2. Новые художник и братухи остаются в черновике, пока заявка не отправлена.
3. «Отправить на проверку» (`do_send` в `user.k`) в одной транзакции переводит заявку в `pending` и через `work_split` выносит новых художника и братух в отдельные заявки с `parent_id` — они уходят админам раньше самой работы.
4. Работа попадает админам только когда решены все дочерние заявки (`work_release` в `admin.k`).
5. Каждому админу создаётся карточка в `cards`; решение выполняется `UPDATE … WHERE status='pending'`, поэтому повторное или чужое нажатие ничего не меняет.
6. При одобрении работа публикуется в канал (`approve_work`), отправителю уходит уведомление, карточки всех админов обновляются.
7. Одобрение художника или братухи ставит `nav_dirty`; `nav_flush` в `main` пересобирает навигационный пост.

Статусы: `draft → pending → approved | rejected`. Виды: `work`, `artist`, `character`.

## Экраны, панель и кнопки

У пользователя одна «панель» — сообщение с кнопками, которое правится на месте; после сообщения пользователя она переотправляется вниз. Логика — `panel_pic` в `ui.k`.

`callback_data` (до 64 байт):

- `m:<что>` — меню: `work`, `artist`, `hero`, `mine`, `rules`, `home`;
- `w:<действие>:<заявка>[:<аргумент>]` — мастер; кнопки, меняющие шаг, помнят шаг (`cbs`), чтобы двойной тап не перескакивал экран;
- `a:<действие>:<заявка>` — решения админа;
- `n:<действие>` — навигационный пост, только админ.

Шаги мастера: работа — `w_media w_artist w_aname w_alink w_chars w_cnew w_caption w_credit w_review w_edit`; художник/братуха — `e_name e_extra e_note e_review e_edit`; админ — `a_fix a_efix a_reason`. Экран по шагу выбирает `show_step` в `wizard.k`.

Новый экран — это: новое состояние в `users.state`, ветка в `show_step`, обработка в `on_wizard`/`in_text`, кнопки с `cbw`/`cbs`, при необходимости баннер.

## Правила Kiva

Подробнее — в шапке `src/core.k` и `.kiva/src/README.md`. Самое важное:

- Сообщения компилятора указывают строки в `build/bot.k` (склеенный исходник), а не в `src/*.k`: ищите текст ошибки по `build/bot.k`.
- Нет типов: всё — 64-битные слова. Указатели и константы C-библиотек передаются числами.
- Нет `&&` и `||`: условия собираются через побитовые `&` и `|` над сравнениями в скобках. Операнды обязаны быть 0 или 1, поэтому `((c = f()) != 0) & …`, а не `(c = f()) & …`.
- Сравнения беззнаковые. `int`-результаты C-функций маскируются `& 0xFFFFFFFF`.
- C-функции с более чем шестью аргументами вызываются неверно — не больше шести; SQL собирается строкой.
- В `for` нет `continue`: он пропускает приращение, используйте `while`.
- Глобальные переменные объявляются в корне файла (`name;`), обнуляются при старте.
- Строки на арене (`alloc`) живут до `arena_reset()` после каждого update. Всё, что должно пережить update или `json_release`, копируется `s_dup`.
- Для строк — `s_eq`, `s_starts`, `s_has`; длины в UTF-16 считает `s_u16` (лимиты Telegram).

## База и JSON

- SQL собирается строкой; пользовательские значения — только через `db_lit`/`sb_lit` (`PQescapeLiteral`), числа — через `sb_int`.
- `db_res` — результат последнего запроса, следующий `db_exec` его освобождает. Строки из `db_val` копируйте `s_dup`, если они нужны после следующего запроса; индексы строк читайте до запросов в цикле.
- Транзакции: `db_begin`/`db_commit`/`db_rollback`; после обрыва связи запрос повторяется только вне транзакции.
- `json_object_set_new`/`json_array_append_new` забирают ссылку; корень освобождается `json_release`. Строки из разобранного ответа (`jstr`) живут до освобождения корня.
- `json_string` возвращает NULL на некорректном UTF-8: пользовательский текст режется `s_cut`/`s_cutc` и экранируется `sb_html`.

## Тесты

`tests/e2e.py`:

- `World` — состояние поддельного Telegram: очередь update, журнал вызовов, сообщения, загрузки, ошибки методов.
- `Ctx` — помощники сценария: `start`, `restart`, `say`, `photo`, `press`, `pick`, `inline`, `last_panel`, `texts`, `sent`, `channel_posts`, `seed`.
- `seed_basic(c)` — художники и братухи для большинства сценариев.
- Сценарий оформляется `@scenario`; каждый получает чистую схему БД. Ошибки — `check(условие, "что не так")`.
- Перед сценариями тест сам собирает `build/tgbot-test` с адресом локального сервера; основной `build/tgbot` для теста не используется.
- Тексты и кнопки в тестах сверяются дословно: меняя формулировки в `ui.k`/`wizard.k`/`post.k`, обновите сценарии.
- Сценарий «без баннеров» запускает бота в пустом каталоге с одной `sql/schema.sql` — так проверяется относительный путь.

Добавляя поведение, допишите сценарий рядом с похожими и проверьте и успешный путь, и отказ/повтор.

## Баннеры и аватар

- Баннер — JPEG 1280×640, имя файла равно имени, которое передаётся в `panel_pic` (`menu`, `media`, `approved`, `rejected`…).
- Правка: `SPECS` в `assets/make_banners.py`, затем `make banners`. Результат детерминирован; руками JPEG не править.
- Стиль и ограничения шрифта — `assets/STYLE.md` (в Waoki нет `№` и `•`).
- Нет файла баннера — экран уходит текстом, в журнал пишется предупреждение. Это допустимый режим.

## Инварианты и грабли

- Все тексты уходят с `parse_mode=HTML`: любой пользовательский текст — через `sb_html`, иначе бот получит ошибку разметки.
- Лимиты Telegram считаются в UTF-16: подпись к медиа — 1024, текст — 4096 (видимую длину ведёт `post_vis`, границу считает `post_limit` в `post.k`).
- Канал должен быть доступен боту на публикацию; при ошибке админ видит понятную причину, а не молчание.
- Админ, ни разу не нажавший `/start`, карточек не получит: бот пишет об этом в журнал при старте.
- Схема: при добавлении колонки нужны и `CREATE TABLE IF NOT EXISTS` с колонкой, и `ALTER TABLE … ADD COLUMN IF NOT EXISTS` для уже существующих баз.
- Ключи поиска (`name_key`, `search`) считает бот: `lower()` в Postgres зависит от локали и может не знать кириллицу.
- Не добавляйте переменные окружения для адреса Bot API, схемы, баннеров и прокси — это осознанное решение. Тест подменяет адрес отдельной сборкой.
- Не редактируйте `build/*` и `.kiva/*`; не коммитьте `.env`.
- Не запускайте тесты против рабочей базы: тест удаляет схему `public`.

## Перед сдачей

1. `make` — основной бинарник собирается.
2. `make test` — все сценарии проходят (или выбранные, если правка точечная).
3. `README.md` и `AGENTS.md` обновлены, если изменились команды, переменные, файлы или поведение.
4. `git diff` не содержит `build/`, `.kiva/`, `.env` и случайных переформатирований.
